# WASM Runbook

Build, verify, embed, and upgrade the `graphlaw-wasm` module. The companion
deep-dive is [wasm-integration.md](wasm-integration.md); wire-level details are
in [abi-reference.md](abi-reference.md).

## What the artifact is

A single `cdylib` built from the `graphlaw-wasm` workspace member
(`wasm/`), exposing three exports over linear memory
(`gl_alloc`, `gl_call`, `gl_free`). All behavior lives in the
safe, native-testable `graphlaw::abi`; the FFI shell (`wasm/src/ffi.rs`) and ABI
metadata (`wasm/src/abi_meta.rs`) are generated by `ggen sync` from
`ontologies/graphlaw-wasm.ttl` — never edit them by hand.

Build command (root of the repository):

```sh
# Canonical relink-8 recipe (SQLRDF-27 verdict, 2026-10-23).
#
# WASI_SDK_PATH points at the unpacked engine cache, used AS the SDK: its
# sysroot carries the legacy-EH C++ runtime matching libduckdb.a. The
# published wasi-sdk-34 sysroot is new-EH-only and fails the final link with
# `_Unwind_GetWasmLPadContext` / `__gxx_wasm_personality_v0` undefined.
# Compile the in-tree wrap shim once:
clang --target=wasm32-wasip1 -c \
  tests/fixtures/wasm-shim/glaw_wrap_shim.c -o tests/fixtures/wasm-shim/glaw_wrap_shim.o
# Then build. RUSTFLAGS carries the EH target feature plus the wrap shim:
# it is the SOLE __wrap provider; --wrap redirects DuckDB's musl-word
# open/openat through the musl->wasi fcntl translator (SQLRDF-27).
WASI_SDK_PATH="$HOME/.frozen-duckdb/cache/v2.0.0-dev-wasm32-wasip1" \
  RUSTFLAGS="-C target-feature=+exception-handling \
-C link-arg=tests/fixtures/wasm-shim/glaw_wrap_shim.o \
-C link-arg=--wrap=open -C link-arg=--wrap=openat" \
  cargo build --locked -p graphlaw-wasm --target wasm32-wasip1 --profile wasm
```

Alternative (not canonical): a plain-open variant of the shim needs
`-C link-arg=--allow-multiple-definition`; the canonical shim + `--wrap` is
preferred. The stub `wasi_posix.c` in the frozen-duckdb checkout is stripped
to libc-gap symbols only and provides no `__wrap_*` — the shim is the sole
provider.

Build prerequisite: `WASI_SDK_PATH` must point at a wasi-sdk root (`bin/clang`
plus a sysroot) — locally the unpacked
`~/.frozen-duckdb/cache/v2.0.0-dev-wasm32-wasip1` tree, whose sysroot carries
the legacy-EH C++ runtime matching `libduckdb.a`; the published wasi-sdk-34
new-EH-only sysroot fails with
`_Unwind_GetWasmLPadContext`/`__gxx_wasm_personality_v0` undefined.
`RUSTFLAGS` must carry `-C target-feature=+exception-handling` so the module
validates under wasmtime's `wasm_exceptions` host, plus the wrap-shim link
args above (sole `__wrap` provider; musl->wasi fcntl translation for DuckDB
COPY egress, SQLRDF-27). The link fails typed at frozen-duckdb-sys `build.rs`
(`WASI_SDK_PATH required`).

Output: `target/wasm32-wasip1/wasm/graphlaw_wasm.wasm` under the `wasm`
profile (`opt-level = "s"`, LTO, `panic = "abort"`, stripped). The unit is ONE
wasm module that must typecheck AND link: `frozen-duckdb` is a normal
dependency of the `graphlaw` crate (no feature gate), dispatched by the wasm
module itself, so it is compiled into the same module — there is no separate
`graphlaw_duckdb.wasm` target (the name is historical — pre-module-dispatch
era) and no "embedded frozen-duckdb" aside.

**Current build state: the one module links frozen-duckdb on every target.**
The frozen-duckdb wasm static archive was rebuilt uniformly new-EH
(`-fwasm-exceptions -mllvm -wasm-use-legacy-eh=0`; clang 24's legacy `try`
emission was the blocker — wasmtime 48 dropped legacy EH and node 26 rejects
mixed-EH modules), so the Tag section that once forced columnar execution
onto the host is gone. `src/lib.rs` / `src/abi.rs` target gates are removed;
the module dispatches `duckdb` itself. The `duckdb` op is module-owned and
unadvertised: it stays off the hashed 14-op table in
`contracts/abi-manifest.json`. The hosting runtime is wasmtime 48
(`graphlaw-run-eh`, feature `runner-eh`) with `wasm_exceptions` enabled;
wasmi 2.0.0 remains only for legacy pre-duckdb artifact courts and rejects
the DuckDB-linked artifact (`exceptions proposal not enabled`).

### Sandbox qualification: what the EH host does and does not contain

`graphlaw-run-eh` (wasmtime 48) fail-closes imports to
`wasi_snapshot_preview1` (`src/bin/graphlaw_run_eh.rs:222-231`) and
preopens no directories. That is the whole containment. It does NOT
provide: fuel or epoch metering (a wasm-infinite loop pins the thread);
a linear-memory ceiling (the 64 MiB `WALL_BYTES` caps the request frame
only, `src/bin/graphlaw_run_eh.rs:28`); environment isolation
(`inherit_env()` hands the guest the full host env,
`src/bin/graphlaw_run_eh.rs:236`). `GRAPHLAW_ATTACH_ROOTS` is a host
library control and is not enforced inside the sandbox — preopening a
directory for the runner bypasses the attach allowlist entirely
(SECURITY.md "EH host sandbox";
[how-to/egress-and-attach-policy.md](how-to/egress-and-attach-policy.md)
"ATTACH policy vs the wasm sandbox").

The pin is minted from this tree with:

```sh

# first — see "Build command").

  RUSTFLAGS="-C target-feature=+exception-handling \

-C link-arg=--wrap=open -C link-arg=--wrap=openat" \
  cargo build --locked -p graphlaw-wasm --target wasm32-wasip1 --profile wasm
```

## Verify the bytes

The artifact is pinned by BLAKE3 digest and byte size, dual-pinned:

- `registry/ARTIFACTS.blake3` — the `wasm` row (pin, size in bytes).
- `priv/graphlaw.wasm.blake3` — sidecar next to the shipped copy
  (`priv/graphlaw.wasm`).

After a build, check both:

```sh
b3sum target/wasm32-wasip1/wasm/graphlaw_wasm.wasm
b3sum priv/graphlaw.wasm
cat priv/graphlaw.wasm.blake3 registry/ARTIFACTS.blake3
```

The digest is a **pin, not a live check**: it was minted at a specific source
state and stays valid only until the next rebuild. After any change to `src/`
or `wasm/`, the artifact changes and the pins MUST be re-minted from a real
build (never hand-written). Both pin files move in the same commit.

Observed reproducibility (from `registry/ARTIFACTS.blake3`): two builds, each
after `cargo clean -p graphlaw-wasm --target wasm32-wasip1 --profile wasm`,
same target dir and machine, produced identical bytes. Not verified across
separate target dirs or machines.

## Unknown-unknown status (G13, v26.10.20)

Besides `wasm32-wasip1`, the `graphlaw-wasm` lib facade builds clean under
`wasm32-unknown-unknown` with **zero `wasi_snapshot_preview1` imports** — the
W03 falsifier. (First receipted before the frozen-duckdb dependency change;
re-run the smoke against the new-EH artifact at the integration receipt —
pending.) The fail-closed smoke is
`scripts/wasm_unknown_unknown_smoke.sh`: it asserts the wasm magic header,
counts WASI imports (any hit exits 1), and loud-skips (exit 3) when no wasm
runtime tooling is on PATH — never a silent pass.

The clock is the one WASI syscall that would otherwise trap: under
`wasm32-unknown-unknown`, `graphlaw-eyeron`'s `current_unix_time`
(`crates/graphlaw-eyeron/src/reasoner.rs`) calls JS `Date.now()` through a
wasm-bindgen extern (`__wbg_now` host glue) instead of `SystemTime::now()`,
which panics there. All other `graphlaw` law/lease paths are clockless by
construction — callers pass `now_unix` explicitly.

## ABI manifest and the breaking-change law

`contracts/abi-manifest.json` is the machine-checked ABI contract: exports
with wasm signatures, the hashed 14-op table in canonical order (`duckdb` is dispatched by the module and omitted from that table until a digest bump), the 128-byte
`OcelCausalFrame` layout, limits, and response envelope — digested by
`manifest_blake3`.

`tests/abi_manifest_court.rs` holds the court: it regenerates the manifest
from live constants and compares. Byte-identical → PASS; divergence that is
only an op-list superset → NON-BREAKING (additive ops); any other divergence
with an unchanged `abi::ABI_VERSION` → FAIL naming "bump ABI_VERSION". The
law: **if the regenerated surface diverges beyond additive ops, bump
`ABI_VERSION` and regenerate the manifest in the same change.** To re-render
after a lawful change: `cargo test -p graphlaw --test abi_manifest_court
write_manifest -- --exact`.

## Differential test as the upgrade witness

`tests/wasm_native_differential.rs` (W08) is the upgrade gate: 35 canonical,
keyless/clockless inputs (every law request carries an explicit `now_unix`)
run natively via `graphlaw::abi::call` and through the compiled wasm module
in a real wasmi runtime, with a raw-byte `assert_eq` per case — the two
execution paths must produce **byte-identical** responses. (wasmi-hosted as
of writing; the DuckDB-linked new-EH artifact is hosted by wasmtime instead
— same byte-identity law, different runner.) Skips are loud
and counted, never silent. If it does not pass byte-identical, the artifact
does not ship.

## Embed in a host

Protocol (all integers are wasm `i32`/`i64`):

1. `gl_alloc(len) -> ptr` — host reserves `len` bytes, writes a UTF-8 JSON
   request there. Returns null above `MAX_REQUEST_BYTES` (16 MiB,
   `src/abi.rs:48`) or when the outstanding-byte cap
   (`MAX_OUTSTANDING_ALLOC_BYTES`, 16 MiB, `src/abi.rs:73`) would be
   exceeded. The 16 MiB request and 16 MiB outstanding caps are uniform
   across targets: the generated `abi_meta` mirrors them
   (`wasm/src/abi_meta.rs:20` request, `wasm/src/abi_meta.rs:29`
   outstanding) and `wasm/src/lib.rs:32-33` asserts the equality at
   compile time, so native and wasm builds present one limit set.
2. `gl_call(ptr, len) -> packed` — runs the request and consumes (frees) the
   request buffer. `packed = (out_ptr << 32) | out_len`.
3. Host reads `out_len` bytes at `out_ptr` (UTF-8 JSON response), then
   `gl_free(out_ptr, out_len)`.

Before calling anything else, check the ABI version your binding was
generated against (`ABI_VERSION = 1`, mirrored as
`graphlaw::abi::ABI_VERSION`) via the `capabilities` op: its `abi_version`
response field must equal that value. A mismatch means the module and the
host binding disagree on the wire surface — refuse, do not probe. (The
compile-time guards pinning the generated `abi_meta` limits and version to
the core's constants live in `wasm/src/lib.rs` — there is no
`gl_abi_version` export.)

A response is always non-empty JSON. A null request pointer or an oversize
length never traps; it returns a typed error response built by the safe core.

For a worked Elixir/Wasmex host, see
[how-to/run-the-wasm-module.md](how-to/run-the-wasm-module.md) and
[wasm-integration.md](wasm-integration.md).

## Upgrade checklist

Run in order; each step gates the next:

1. Bump the root `graphlaw` version and the `graphlaw-wasm` version
   **together** (they were allowed to skew before W09; they must not again).
   If the ABI surface changed beyond additive ops, bump `ABI_VERSION` and
   regenerate `contracts/abi-manifest.json` in the same change
   (`cargo test -p graphlaw --test abi_manifest_court write_manifest --
   --exact`); the court must pass byte-identical.
2. Build with the canonical relink-8 recipe (build command above):
   `WASI_SDK_PATH` at the frozen-duckdb cache SDK root plus `RUSTFLAGS`
   with `-C target-feature=+exception-handling` and the wrap-shim link args.
3. Re-pin the dual digests from the real build: update the `wasm` row in
   `registry/ARTIFACTS.blake3` (header line too: `digest=`, `size=`,
   `pin-source=`) and rewrite `priv/graphlaw.wasm.blake3` (plus refresh
   `priv/graphlaw.wasm`) in the same commit.
4. `cargo test --test wasm_native_differential` — 35 cases byte-identical
   native vs wasm; the upgrade witness (W08). Skips must be zero or loud.
5. `cargo test --test wasm_abi` — drives every op and dialect through the
   compiled module in wasmi exactly as a host would (`GRAPHLAW_WASM=<path>`
   to test the prebuilt artifact instead of a fresh build). wasmi 2.0.0
   caveat: it rejects the DuckDB-linked new-EH artifact; wasmi courts are
   for the legacy pre-duckdb pin only — the current artifact's host is
   `graphlaw-run-eh` (wasmtime 48).
6. `cargo test --test abi_manifest_court` — manifest regenerates
   byte-identical (or additive-only) against the new version.
7. Update the pin section of [wasm-integration.md](wasm-integration.md).
8. Tag the release.
