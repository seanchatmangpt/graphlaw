# TypeScript API reference

The `graphlaw` npm package wraps the `graphlaw-wasm` ABI in a typed client.
Everything below is the public surface exported from `graphlaw` (see
`js/npm/src/index.ts`).

## Main export

### `initGraphlaw(options?): Promise<WasmAbi>`

Loads the pinned `graphlaw.wasm` module once per process, verifies its SHA-256
against the pinned digest, and instantiates it. Returns the raw wire handle.
The digest lives in `src/generated/artifact-meta.ts`, generated by
`scripts/build.mjs` — which itself verifies the checked-in
`priv/graphlaw.wasm.sha256` pin and fails the build on drift.
Options (`GraphlawInitOptions`):

```ts
{ wasmBytes?: Uint8Array; skipShaCheck?: boolean }
```

`wasmBytes` bypasses the cache and (unless `skipShaCheck: true`, dev only)
still gets digest-verified. Failures throw `GraphlawInitError` (module load or
instantiation failure) or `GraphlawIntegrityError` (digest mismatch).

The artifact is a `wasi_snapshot_preview1` cdylib, but the package does not
use Node's WASI implementation (and has no external WASI shim). It supplies
its own zero-dependency stub set for the 7 trivial preview1 imports the
module needs — identical on Node and browser (`src/runtime.ts`,
`src/runtime.web.ts`).

### `createClient(): Promise<Graphlaw>`

Initializes the engine and returns a typed client. Awaits init immediately so
init failures surface at construction, not on the first call.

### The `Graphlaw` class

One method per ABI op, plus a `tryX()` variant for each. `X()` throws
`GraphlawRefusalError` on a `{ok: false}` envelope; `tryX()` returns the
envelope verbatim as `AbiResult<T>` instead.

| method | request | response (on `ok: true`) |
|---|---|---|
| `capabilities()` | `CapabilitiesRequest` (empty) | `AbiOk<CapabilitiesResponse>` |
| `sniff(text, hint?)` | `SniffRequest` | `AbiOk<SniffResponse>` |
| `parse(request)` | `ParseRequest` | `AbiOk<ParseResponse>` |
| `convert(request)` | `ConvertRequest` | `AbiOk<ConvertResponse>` |
| `canonical(data: DataSpec)` | `CanonicalRequest` | `AbiOk<CanonicalResponse>` |
| `sparql(request)` | `SparqlRequest` | `AbiOk<SparqlResponse>` |
| `shacl(request)` | `ShaclRequest` | `AbiOk<ShaclResponse>` |
| `shex(request)` | `ShexRequest` | `AbiOk<ShexResponse>` |
| `n3(text)` | `N3Request` | `AbiOk<N3Response>` |
| `entail(request)` | `EntailRequest` | `AbiOk<EntailResponse>` |
| `datalog(request)` | `DatalogRequest` | `AbiOk<DatalogResponse>` |
| `hooks(request)` | `HooksRequest` | `AbiOk<HooksResponse>` |
| `law(request)` | `LawRequest` | `AbiOk<LawResponse>` |
| `policy(request)` | `PolicyRequest` | `AbiOk<PolicyResponse>` |

Each method has a matching `tryCapabilities()`, `trySniff()`, ... `tryPolicy()`
returning `AbiResult<T>`.

## graphlaw/raw

For faithful passthrough of the JSON ABI without the typed layer. These
functions never throw for ABI outcomes; the envelope comes back verbatim.

```ts
import { callRaw, callRawJson } from 'graphlaw';

const envelope = await callRaw({ op: 'sniff', text: '<a> <b> <c>.' });
// { ok: true, ... } | { ok: false, error: { kind, engine, dialect, message, details? } }

const responseJson = await callRawJson('{"op":"sniff",...}');
```

- `callRaw(request: Record<string, unknown>): Promise<AbiResult<Record<string, unknown>>>`
- `callRawJson(requestJson: string): Promise<string>`

Raw requests must respect `LIMITS.max_request_bytes` (16 MiB) and the other
registry limits; see the [ABI reference](abi-reference.md).

## Types

### Hand-written (`src/types.ts`)

- `Term` — RDF term union: `{type: 'uri'|'bnode'|'triple'; value: string}` or
  `{type: 'literal'; value: string; datatype: string; 'xml:lang'?}`. Appears in
  SPARQL solution cells and ShEx entries.
- `DataSpec` — the shared way to hand the engine a document:
  `{text, dialect?, hint?, base?}`. The dialect is sniffed when omitted.
- `AbiOk<T>` — success envelope `{ok: true} & T`.
- `AbiRefused` — failure envelope `{ok: false, error: {kind, engine, dialect,
  message, details?}}`.
- `AbiResult<T>` — `AbiOk<T> | AbiRefused`, returned by `tryX()` variants.

### Generated (`src/generated/types.ts`)

Regenerated from the registry by `npm run gen`; do not edit by hand.

Per-op request/response interfaces: `CapabilitiesRequest/Response`,
`SniffRequest/Response`, `ParseRequest/Response`, `ConvertRequest/Response`,
`CanonicalRequest/Response`, `SparqlRequest/Response`,
`ShaclRequest/Response`, `ShexRequest/Response`, `N3Request/Response`,
`EntailRequest/Response`, `DatalogRequest/Response`,
`HooksRequest/Response`, `LawRequest/Response`,
`PolicyRequest/Response`. `SparqlResponse` is a union discriminated by
`kind`: `SparqlSolutions | SparqlGraph | SparqlBoolean`.

Models:

| type | shape |
|---|---|
| `Lease` | `{id, holder, ceiling, scope, expires_unix, issued_unix}` |
| `SignedLease` | `{lease, attestation}` |
| `Receipt` | transition record; optional `lease_id?`, `plan_sha256?`, `subject_sha256?` |
| `Attestation` | `{payload_sha256, key_id, signature}` |
| `Plan` | `{actions, goal, goal_not}` |
| `Action` | `{name, pre, pre_not, add, del}` |
| `PolicyEntry` | `{state, action, outcomes}` |
| `PolicyOutcome` | `{state, probability_ppm}` |

Closed unions:

- `Ceiling` — `observe | select | construct`
- `LeaseReason` — `expired | out_of_scope | ceiling | bad_signature |
  untrusted_key | clock_skew`
- `ReceiptReason` — `unattested | bad_signature | untrusted_key`
- `RefusalKind` — `NotSemanticContent | Ambiguous | EngineRejected |
  Unsupported | ResourceLimit`
- `RefusalCode` — `Refused | ResourceLimit | PlanRefused | ReceiptRequired |
  ReceiptRefused | LeaseRefused | NotAdmitted | UnverifiedLeaseRefused |
  PolicyRefused`
- `PolicyRefusalKind` — `MissingEntry | InventedOutcome | BadMass | DeadEnd |
  Malformed`
- `Engine` — `PurRdf | Eyeron`
- `DialectName` — request-side wire names: `turtle | trig | ntriples |
  nquads | rdfxml | jsonld | yamlld | trix | hextuples | n3 | sparql | shexc |
  shexj`
- `DialectResponseName` — response-side Rust variant names: `Turtle | TriG |
  NTriples | NQuads | RdfXml | JsonLd | YamlLd | TriX | HexTuples | N3 |
  Sparql | ShExC | ShExJ`
- `Regime` — `simple | rdf | rdfs | owl-rl | d`

Constants:

```ts
import { ABI_VERSION, LIMITS } from 'graphlaw';

ABI_VERSION; // 1
LIMITS.max_request_bytes; // 16777216 (16 MiB)
LIMITS.max_outstanding_alloc_bytes; // 256 MiB
// plus hooks_*, n3_*, max_plan_*, max_policy_entries, max_atoms_per_field,
// max_json_depth — mirrored from the registry and test-verified against it.
```

## Errors

All error classes extend `GraphlawError`, which carries a `code: string` and
is `instanceof`-safe across ES2022 targets.

| class | `code` | when thrown |
|---|---|---|
| `GraphlawInitError` | `init` | module load, instantiation failure, a preview1 import called before instantiation, or `proc_exit` |
| `GraphlawIntegrityError` | `integrity` | wasm SHA-256 mismatch; carries `expected`/`actual` |
| `GraphlawAllocRefusedError` | `alloc_refused` | `gl_alloc` refused: limits or alloc cap |
| `GraphlawRequestTooLargeError` | `request_too_large` | over 16 MiB; carries `observed`/`max` |
| `GraphlawRefusalError` | `details.code` or `refused` | ABI refusal from an `X()` method |

`GraphlawRefusalError` also carries the envelope fields `kind`, `engine`, and
`dialect`. Its `details` is the optional refusal detail object keyed by
`details.code` (a `RefusalCode`); its per-code fields are documented in
[Refusals](../refusals.md). Engines-level refusals (bad syntax, unknown query
form) carry no `details`; decoders must treat `details` as optional and
unknown codes as open. Use `refusalToError(refusal)` to map a raw refusal
envelope to `GraphlawRefusalError`.

## Versioning

The npm package version always equals the crates.io `graphlaw` version it was
generated from; both are calendar-versioned (for example `26.10.13`). The
wire ABI itself is versioned separately: `ABI_VERSION` is currently `1` and
evolves additively only — see [API stability](../api-stability.md).

## Provenance

The generated types are a projection of `registry/capability-registry.json` —
the same CI-checked document the Rust ABI tables emit. Hand edits to
`npm/src/generated/types.ts` fail the CI drift check. The handwritten residue
is ledgered in `js/HANDWRITTEN.md`; edit the source of truth and regenerate
with `npm run gen`.
