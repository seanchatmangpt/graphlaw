## Generator-of-record finding (governs every RECONCILE-PACK verdict)

`ggen/sql-dialect/statement_classes.ttl:1-2` is headed "Generated by ggen from
the DuckDB PEG Statement alternatives. Do not edit by hand." The generator is
`ggen/sql-dialect/extract_statements.py`, which reads the frozen DuckDB PEG
grammar (`src/parser/peg/grammar/statements/common.gram`, pinned at
`duckdb commit b6013f7aa2`, script line 4) and writes
`ggen/sql-dialect/ontology/statements.ttl`; `statement_classes.ttl` is a
sibling projection. `extract_statements.py:112-115` enforces example-map and
extension-map drift detection (exit 1 on mismatch), and its missing-tree
failure path (lines 105-110) names the committed TTL as the contract.

Consequence: any "add the term to the pack" verdict must be executed by
changing the generator (or adding a new projection leg) and regenerating,
never by hand-editing the TTLs. This matches repo doctrine — but note the
pack's upstream of record is the frozen DuckDB PEG grammar, while the
compiler's canonical graph is `ontologies/sql-ast.ttl`. Two upstreams is the
root cause of the D1–D4 drift; see the governance decision under D4.

### D4 — Operator enum (15 IRIs reported / 15 tokens) + governance decision

**Verdict: RECONCILE-COMPILER (scoped) + pack mirrors the legacy IRI alias
window only.**

- Compiler: `src/sql_ast.rs:559-571` (`Operator::from_iri` — 9 legacy IRIs
  `sql:Equals`…`sql:Like`, commented "Legacy axiom IRIs ... stay legal
  (SQLRDF-01 alias window)"); `:574-606` (`from_token` — 15 tokens
  `= != < <= > >= AND OR + - * / % LIKE ILIKE`, refusal arm OPERATOR_TOKEN).
  Note: L28's row said "15 IRIs"; `from_iri` actually carries 9 IRIs and
  falls through to `from_token` for everything else (disclosed correction).
- Pack: zero operator vocabulary (L28 grep, drift report line 44, exit 1).
- Canonical: `ontologies/sql-ast.ttl:190` (`sql:operator`), `:257-266`
  (`sql:Equals` … as `sql:Operator` individuals with token labels), `:378-385`
  (legacy IRI alias window in SHACL).

Adjudication: the 15-token enum is the normative section-4 conformance surface
(rec text); the 9 IRIs are the SQLRDF-01 legacy alias window. The DuckDB PEG
grammar (pack's upstream) is not the generator of record for this enum — the
conformance text + canonical graph are. Therefore: declare in the pack only
the 9 legacy IRI individuals, projected from `sql-ast.ttl:257-266` (D1 route).
The token enum itself stays compiler+rec-governed; any new operator
token/IRI is a section-4 amendment requiring rec text + `sql-ast.ttl` +
`from_token`/`from_iri` + courts together — never a pack-only or
compiler-only change.

**Governance decision (special adjudication #3 — mirror or lead?):**
Per ontology-first doctrine (canonical graph = source, generated artifacts
project): **the pack mirrors; the canonical graph leads** for clause/operator
vocabulary. The pack legitimately *leads* on statement-kind coverage (it scans
the frozen upstream grammar and can discover a statement before the compiler
grows an arm — D6 is that boundary working correctly). Hierarchy:

```
DuckDB PEG grammar (frozen b6013f7aa2)
        │ extract_statements.py
        ▼
ggen/sql-dialect/ontology/statements.ttl   ← statement-kind coverage (pack leads, legitimately)
ggen/sql-dialect/statement_classes.ttl     ← class projection
        ▼ (proposed) ontology→pack projection leg
ontologies/sql-ast.ttl                     ← canonical sql-rdf vocabulary (leads)
        ▼ src/sql_ast.rs + docs/reference/sql-rdf-rec.md
compiler enum gates + courts
```

The mirror leg (sql-ast.ttl → statement_classes.ttl) does not exist today —
that is the root cause of D1–D4. Plan: build it once; D1/D2/D3/D5 and D4's
alias-IRI half all land through it.

### D6 — `sql:ConnectStatement` / `sql:DisconnectStatement` (pack-only, REFUSAL-02)

**Verdict: ACCEPT-DRIFT (keep-as-documented-unimplemented).**

- Pack: `statement_classes.ttl:110-114` (owl:Class declarations);
  `ontology/statements.ttl:172-180` (StatementKind entries, orders 34-35,
  examples "CONNECT LOCAL" / "DISCONNECT").
- Compiler: `src/sql_ast.rs:2160-2164` — explicit
  `RefusalCode::UnimplementedStatement` (REFUSAL-02), typed, statement IRI as
  ident. Never silently dropped.

Reasons to keep rather than remove:
1. The pack's coverage is a faithful projection of the frozen DuckDB PEG
   grammar (`extract_statements.py` scans the `Statement` rule; Connect/
   Disconnect are real alternatives in `common.gram`; map entries at
   `extract_statements.py:75-76`). Removing them would make the pack a false
   statement about its pinned upstream.
2. Removal is mechanically refused: deleting the map entries trips the
   example-map drift check (`extract_statements.py:112-115`, exit 1) against
   the PEG scan — the generator is designed to refuse exactly that edit.
3. The typed refusal IS the lawful pack-leads/compiler-lags boundary. The
   obligation is documentation only: mark these two kinds
   pack-known/compiler-unimplemented (REFUSAL-02) in the refusals register
   (`docs/refusals.md`) or pack README — NOT in the generated TTL.

### D7 — `sql:name` / `sql:example` / `sql:order` metadata predicates

**Verdict: ACCEPT-DRIFT, formalized as a documented scope boundary.**

  `sql:StatementKind` nodes (and `sql:Extension` nodes, lines 185-238).

**Boundary text (final form, for adoption in pack docs / refusals register):**

> Pack metadata vocabulary — `sql:name`, `sql:example`, `sql:order` (on
> `sql:StatementKind` nodes) and `sql:name`, `sql:setup`, `sql:check`,
> `sql:expect`, `sql:order` (on `sql:Extension` nodes) — is pack-side
> vocabulary and is outside the compiler's 14-predicate closed enum by scope,
> not by acceptance: the enum gate is per-node and applies only to SELECT
> statement nodes (`src/sql_ast.rs:1703-1718`). Attaching any non-enum
> `sql:`-namespaced predicate to a SelectStatement node refuses typed
> REFUSAL-01 (UNKNOWN_STATEMENT_PREDICATE). Consumers must not reuse pack
> metadata predicates on statement nodes.
